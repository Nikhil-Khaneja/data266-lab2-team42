# Part 2 - Fine-tuning Stable Diffusion 1.5 for Naruto-style images (Nikhil, baseline)

This folder holds Nikhil's complete Part 2 pipeline (tasks 2.1-2.4):

* clean and split `lambdalabs/naruto-blip-captions`;
* fine-tune Stable Diffusion 1.5 with **two LoRA runs that differ only in rank (4 vs 16)**;
* generate the 20 fixed prompts with the base model and both runs;
* measure quality (KID), prompt alignment (CLIP score), seed diversity (LPIPS), cost, NSFW safety and
  memorization.

The team's **graded** Part 2 system is Anushka's rank-16 run, in [`../member-anushka/`](../member-anushka/).
This implementation is the partner's working pipeline that the lab requires (requirements S.2).

**Result in one line:** the rank-16 run cuts KID against the real test images from 0.118 (base) to
**0.023**, half of rank 4's 0.051, at the same cost (0.36 GPU-hours, 4.2 GB peak) and the same CLIP score.

All numbers below are printed by [`notebooks/p2_finetune.ipynb`](notebooks/p2_finetune.ipynb). It was
executed on an RTX 4090 at commit `67fe603` with seed 266, and saved to `eval/`. All paths are relative to
`part2/member-nikhil/`.

## 2.2 Fine-tuning

The official diffusers `train_text_to_image_lora.py` script ([`src/part2/diffusers_scripts/`](src/part2/diffusers_scripts/)),
driven by [`src/part2/train_runs.py`](src/part2/train_runs.py). Both runs share every setting except the rank.

| Setting | Run 1 | Run 2 |
|---|---|---|
| LoRA rank | 4 | 16 |
| Trainable parameters | 797,184 | 3,188,736 |
| Learning rate | 1e-4, constant, no warm-up | 1e-4, constant, no warm-up |
| Steps | 1,200 | 1,200 |
| Batch | 1 × gradient accumulation 4 = 4 | 1 × 4 = 4 |
| Resolution / precision | 512, fp16 | 512, fp16 |
| Peak GPU memory (`max_memory_reserved`) | 4.12 GB | 4.15 GB |
| Training time | 1,323.8 s (0.368 GPU-h) | 1,304.5 s (0.362 GPU-h) |

Both runs fit the 16 GB budget with a wide margin. The notebook reuses adapters already trained on
2026-11-14 when their rank and step count match (`"reused": true` in `eval/part2_training.json`). The loss
curve of each run is plotted from its `train.log`.

## 2.3 Image generation

[`src/part2/generate.py`](src/part2/generate.py) uses the 20 fixed prompts in
[`../eval/part2_prompts.json`](../eval/part2_prompts.json), committed on 2026-10-27, before training. The prompts
are in-domain, out-of-domain and compositional. Each prompt is generated with seeds 0 and 1, 30 sampling
steps and guidance 7.5, giving **120 images** (40 per model). The notebook shows side-by-side grids
(base | rank 4 | rank 16) for 8 prompts.

The Stable Diffusion safety checker runs on every image. A flagged image is published and rated as a black
image. Its unfiltered copy stays local (`generated/raw/`) and is used only for the metrics, so a false
positive does not count as a black image in KID, CLIP or LPIPS.

## 2.4 Evaluation

| Measurement | Base SD 1.5 | LoRA rank 4 | LoRA rank 16 (final run) |
|---|---|---|---|
| Primary: KID vs test images (mean ± std) | 0.118 ± 0.012 | 0.051 ± 0.008 | **0.023 ± 0.006** |
| Primary: CLIP score (40 images) | 0.312 | 0.305 | 0.304 |
| Secondary: LPIPS between seeds (diversity) | 0.686 | 0.674 | 0.661 |
| Human: blinded win rate vs base | – | – | not rated (see [Known gaps](#known-gaps)) |
| Efficiency: GPU-hours / peak memory | – | 0.368 / 4.12 GB | 0.362 / 4.15 GB |
| Safety checker flags (of 40) | 0 | 4 | 7 |

Source: `eval/part2_metrics.json`, `eval/part2_training.json`, and the generation cell.

**Final run: rank 16.** It has the same data, steps and learning rate as rank 4, and its KID is less than half
of rank 4's (0.023 vs 0.051). Its CLIP score is the same (0.304 vs 0.305) and its compute is the same. The cost
is a small loss of seed diversity (0.661 vs 0.674). KID uses only 20 in-domain images per model, so it is noisy.
Still, the gap between the runs (0.027) is about five times rank 16's standard deviation (0.006).

### Failure modes (picked by the metrics, not by hand)

1. **The trained style overrides out-of-domain prompts.** Both LoRA runs draw "a photorealistic astronaut on
   the moon" as a flat anime illustration. For "a steampunk city skyline at sunset" the final run loses most of
   the sunset (CLIP 0.309 vs 0.337 for the base model).
2. **Compositional prompts lose attributes.** "Three characters sitting around a campfire at night" becomes a
   grey daytime sketch with no fire (CLIP 0.279 vs 0.324). In "two characters, one in red and one in blue", the
   colours are not bound to the right character.
3. **Less variety inside the domain.** The two seeds of an in-domain prompt are more alike (LPIPS 0.632) than
   those of a compositional prompt (0.710). No pair is near-identical; the closest scores 0.561.
4. **Safety-checker false positives.** 10 of the 11 flagged images are in-domain "a man ..." prompts from the
   two LoRA runs; the base model had none. The checker reacts to the anime style.

### Safety (C4)

* **License.** The dataset contains copyrighted characters, so the dataset, both adapters and the generated
  images are for non-commercial research and education only.
* **NSFW.** The safety checker is on for every image. It flagged 11 of 120, none from the base model and
  mostly in-domain "a man ..." prompts, which points to the anime style triggering it. Flagged images are
  published black.
* **Memorization.** For the final run's in-domain generations, the nearest training image by CLIP similarity
  scores at most 0.916 (`eval/part2_memorization.json`). The notebook shows the three closest pairs side by
  side for visual inspection.
